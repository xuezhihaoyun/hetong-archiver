事项：合同归档与统一命名工具（Skill），无文号，主办＝叶律师本人。
类型：**运维代码**。
仓库：`https://github.com/xuezhihaoyun/hetong-archiver`（private，两台 Mac 共用）。

## 接手纪律（必须遵守）

1. **只读三处即可接手**：本文件 → `工作日志.md` 文首的「速读区」＋「口径卡」（约 3KB）。当前节点、待叶律师定、未关闭待办、已查成果、已排除方向都在里面。
2. **禁止全量通读仓库**。各文件用途见下方地图，需要哪份按文件名定点读。
3. **合同数据不在这个仓库**。合同文件在 iCloud 的 `📚合同审查/`，客户别名/固定规则在 `<root>/.合同归档/config.json`。本仓库只放代码、文档、`config.example.json`。
4. **接手先复述**：读完后第一次回复开头用不超过三行说明：当前节点、下一步、待叶律师定。说完直接干；只有指令与速读区冲突（如要做的已在「已排除」、涉及「待叶律师定」）时才先问。
5. **不重复做**：改判定逻辑、调命名规则前先看速读区「已查成果」「已排除」和 `变更记录.md` 的踩坑表，别把修过的 bug 再犯一遍。
6. **随做随写**：改了口径、修了 bug、叶律师定了一件事，立即更新速读区并在流水区记一笔，不等会话结束。
7. **一事一日志**：只续写 `工作日志.md` 这一份，不得另建。流水区只增不改。
8. **改完要同步**：`git add -A && git commit && git push`，否则另一台机器拿不到。

## 文件夹地图

| 位置 | 内容 | 读取规则 |
|---|---|---|
| `SKILL.md` | agent 入口：五步工作流、六级判定、红线、汇报口径 | 必读 |
| `scripts/dispatch.py` | 归档分派（默认演练，`--apply` 执行，`--fallback` 收其他） | 改判定逻辑看这里 |
| `scripts/rename.py` | 统一命名（默认演练），出台账 CSV | 改命名规则看这里 |
| `scripts/parties.py` | 合同当事人主体抽取 | 主体抽错先看这里 |

| `scripts/init_config.py` | 扫 `00.已经处理` 反推客户名单 | 换机/新增客户后跑 |
| `references/命名规则.md` | 文件名各段口径 | 命名有争议时以此为准 |
| `references/归档规则.md` | 判定顺序、主体抽取实现、四个去向 | 归档判错时以此为准 |
| `references/客户归属备忘.md` | **已拍板的客户对应关系** | 遇归属问题先查这里，别重新问 |
| `变更记录.md` | 版本沿革、口径迭代、踩过的坑 | 改动前先读 |
| `排错.md` | 8 类常见故障与回退方法 | 出问题先查 |
| `归档日志/`、`改名台账/` | 运行记录（`gitignore` 未入库，各机器本地） | 出问题按台账反查 |

## 三条硬红线（改代码也不许破）

1. 从不删除文件；重名不覆盖（自动加 `-2`）
2. 演练是默认模式，`--apply` 才动文件；AI 不得自行加 `--apply`
3. 客户归属有歧义 → 问人，不猜
